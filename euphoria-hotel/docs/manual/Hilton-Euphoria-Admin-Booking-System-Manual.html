System Overview

The system has three manager-facing areas: the public website, the booking/admin dashboard, and the CMS content dashboard. The booking dashboard controls hotel operations; the CMS controls editable website content.

Rooms

Rooms Listing And Room Detail Pages

The rooms section is where guests compare rooms before booking. Pricing, capacity and active/inactive room status come from the room records used by the booking engine.

Rooms listing page.
Room detail page for a selected room.

Manager checks

  • Room names, prices and descriptions should match the hotel's approved tariff.
  • Inactive rooms should not be treated as bookable.
  • Room images should represent the exact room category where possible.
  • Guests should be able to move from room detail to reservation without errors.

Access

Admin Login

Only authorized users should access the admin or CMS areas. After handover, the hotel should immediately update the manager password and keep credentials private.

Admin sign-in screen with the hotel logo.
Password rule: use at least 12 characters with uppercase, lowercase, a number and a symbol. Do not reuse a personal password.

Block Dates

Closing Dates For Maintenance Or Offline Use

Use block dates when a room should not be sold online even though it exists in the room catalogue. Examples include maintenance, internal reservation, private hold or room inspection.

Block dates page.
1Select the affected room.
2Select from and to dates.
3Add a clear reason so future staff understand why the room is closed.
4Remove the block when the room becomes available again.
Rooms

Room Management

The rooms page controls room records used by the website and booking engine. Edit room details carefully because public prices and availability depend on this data.

Room management page.
Operational caution: changing a room price affects new bookings going forward. Existing bookings retain their stored pricing unless manually adjusted in the database.
Inquiries

Contact And Conference Follow-Up

Inquiries are messages from contact and conference forms. A manager should review unread inquiries daily and assign follow-up where necessary.

Inquiries inbox.

Recommended process

  1. Open each unread inquiry.
  2. Confirm whether it is general contact, reservation help or conference/event related.
  3. Call or email the guest using the provided contact details.
  4. Mark as read once the inquiry has been handled.

Operating Rhythm

Daily, Weekly And Monthly Checklist

This checklist helps the manager keep the system accurate and reliable.

Daily

  • Review new and pending bookings.
  • Check today's arrivals and departures.
  • Review unread inquiries.
  • Confirm blocked dates for unavailable rooms.

Weekly

  • Review room prices and active room status.
  • Export bookings for reconciliation.
  • Review admin users and disable old accounts.
  • Check public pages for outdated information.

Monthly

  • Review revenue and booking reports.
  • Update seasonal room rates if required.
  • Audit password and user access.
  • Confirm SEO titles and descriptions remain accurate.
Final handoff reminder: after delivery, the hotel manager should change the admin password, confirm Paystack credentials, confirm email sending credentials, and verify that the custom domain points to the final production deployment.
